# 写作指南

日常只有三种操作：**建文件 → 写内容 → 推送**。下面按顺序说。

---

## 一、新建一篇文章

在 `src/content/blog/<分类名>/` 下新建 `.md` 文件。**目录名就是分类**，文件名就是网址。

```
src/content/blog/
├─ tech/                     ← 分类「tech」，对应 /categories/tech/
│  ├─ astro-static-site.md   ← 网址是 /posts/tech/astro-static-site/
│  └─ my-new-post.md         ← 网址是 /posts/tech/my-new-post/
├─ notes/                    ← 分类「notes」
│  └─ hello-world.md
└─ 直接放这里.md              ← 不在子目录里的会归到「未分类」
```

**文件名建议**：全小写英文 + 短横线，例如 `my-first-post.md`。
因为文件名会变成网址，用中文虽然也能跑（网址会被转义成一长串 `%E4%B8%AD%E6%96%87...`），但不好看也不好分享。

分类名同理，建议用英文（`tech`、`notes`、`reading`），或者你能接受网址里出现中文转义也行。

---

## 二、填开头的"元信息"

文件最上面用三条横线包起来的部分叫 frontmatter，是这篇的配置：

```markdown
---
title: 我的新文章
description: 一句话摘要，会出现在文章列表、搜索结果和分享卡片里
pubDate: 2026-02-01
tags: ['技术', '随笔']
draft: false
pinned: false
---

正文从这里开始……
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✅ | 文章标题 |
| `description` | ✅ | 一句话摘要，**别写太长**，列表和搜索结果都用它 |
| `pubDate` | ✅ | 发布日期，写 `2026-02-01` 这种格式即可 |
| `tags` | | 标签数组，可多个：`['技术', '随笔']` |
| `draft` | | `true` = 草稿，正式构建不发布（本地仍可预览） |
| `pinned` | | `true` = 置顶，会出现在首页"精选"大卡片里 |
| `updatedDate` | | 修订日期，填了会在文章页显示"修订于 …" |
| `cover` | | 封面图，放 `public/` 下或外链 |

## 三、写正文

标准 Markdown，常用的都有：

```markdown
## 二级标题
### 三级标题

普通段落。**加粗**、*斜体*、`行内代码`、[链接](https://example.com)。

- 无序列表
- 第二项

1. 有序列表
2. 第二项

> 引用块

| 表头 | 表头 |
| --- | --- |
| 单元格 | 单元格 |
```

代码块带上语言就会自动高亮：

````markdown
```js
function hello(name) {
  console.log(`你好，${name}`);
}
```
````

**站内链接**：因为站点可能部署在子路径下，正文里链接到站内页面时用相对路径最稳：

```markdown
看[标签页](../../../tags/)
```

**插入图片**：图片放 `public/images/` 下，然后引用 `/images/文件名.jpg`：

```markdown
![图片说明](/images/screenshot.png)
```

## 四、本地预览

```bash
npm run dev        # 打开 http://localhost:4321
```

改 Markdown 或改代码，浏览器会**自动刷新**，不用重启。写完关掉终端即可。

想验证"正式构建后的样子"（含搜索索引）：

```bash
npm run build && npm run preview
```

---

## 五、发布

```bash
git add .
git commit -m "post: 我的新文章"
git push
```

推上去之后 Cloudflare Pages 会自动重新构建，大约 30 秒~2 分钟后线上更新。
构建进度可以在 Cloudflare 的 **Workers & Pages → 你的项目 → Deployments** 里看。

> 如果还没部署过，先看 [部署指南](部署指南.md)。

## 六、改名字 / 头像 / 简介 / 社交链接

全在 `src/config.ts`：

```ts
sidebar: {
  avatar: '/avatar.svg',        // 头像：图片放 public/ 下，这里写 /文件名
  name: '若溪',                 // 边栏显示的姓名
  latin: 'Ruoxi',               // 英文名，留空不显示
  bio: '写代码，也写字。',        // 一句话签名
  location: 'Hangzhou, CN',     // 所在地，留空不显示
  nav: [ /* 边栏导航，增删条目改这里 */ ],
},
social: [
  { label: 'GitHub', href: 'https://github.com/你的账号', icon: 'github' },
  { label: '邮箱', href: 'mailto:你的邮箱', icon: 'mail' },
  { label: 'RSS', href: '/rss.xml', icon: 'rss' },
],
```

**换头像三步**：

1. 把图片复制到 `my-blog/public/`，例如 `public/avatar.jpg`
2. 改 `avatar: '/avatar.jpg'`
3. 刷新（或 `npm run dev` 下自动刷新）

建议图片是正方形、200×200 以上、1 MB 以内；显示时会自动裁成圆形。

**首页那句自我介绍**、**入场加载页的站名** 分别在：

```ts
title: '若溪的小窝',        // 站点标题（浏览器标签、页脚、入场页）
tagline: '把想法写成文章，把日子过成诗',   // 首页那句"我是若溪，把想法写成文章…"
description: '一个记录技术、阅读与生活的个人博客。',  // 首页简介 + SEO 描述
author: '若溪',            // 作者名
```

## 七、加友情链接

编辑 `src/data/friends.ts`，在数组里追加一项：

```ts
{
  name: '某某的博客',
  url: 'https://example.com',
  desc: '一句话介绍',
  initial: '某',        // 头像里显示的字，不填就取名字第一个字
  color: '#2563eb',     // 头像底色，不填就是浅灰
},
```

侧边栏显示前 5 个，`/friends` 页面显示全部。

## 八、常用命令速查

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 本地开发，改文件自动刷新 |
| `npm run build` | 构建（同时生成搜索索引） |
| `npm run preview` | 预览构建结果 |
| `npm run serve` | 同上，但用内置的零依赖静态服务 |
| `npm run cf:dev` | 本地模拟 Cloudflare 环境（能测点赞/阅读量接口） |

## 九、常见问题

**改了没生效？**
`npm run dev` 下会自动刷新；如果开的是预览，需要重新 `npm run build`。线上则是等 Cloudflare 部署完成。

**文章没出现在列表里？**
检查 `draft` 是不是 `true`，以及 `pubDate` 是否写成了未来日期（未来日期不会隐藏，但排序会跑到最前面）。

**文章网址里有一串 %E4%B8%AD？**
分类名或文件名用了中文。想改就重命名文件/目录，**注意改后旧链接会失效**。

**想让某篇置顶？**
在 frontmatter 里加 `pinned: true`，它会出现在首页的"精选"大卡片里。

**搜索结果里没有新文章？**
搜索索引是构建时生成的，本地要 `npm run build`；线上推送后会自动重建。
